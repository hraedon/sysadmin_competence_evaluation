## Gaps to flag

- **Calibration harness untested with real concurrency**: The worker pool is correct by inspection but has never run with actual parallel LLM calls. A smoke test with `--concurrency 2 --scenario <one-scenario>` against a real endpoint would confirm. (`calibration/run.mjs:271-282`)
- **Migration 005 is inspector-guarded but not tested against PostgreSQL**: The `sa.inspect(conn).get_columns("environments")` check works on SQLite (where tests run) but the `drop_column` path is only exercised on PostgreSQL. SQLite tests use `create_all` which bypasses Alembic entirely. (`platform/lab-controller/app/migrations/versions/005_drop_env_guac_connection_id.py:24`)
- **No regression test for ARCH-15 column removal**: The existing tests implicitly verify `load_environments()` works without the field, but there's no explicit `assert not hasattr(env, 'guac_connection_id')` test. A future refactor could re-add the column without detection. (`platform/lab-controller/tests/test_integration.py`)
- **ARCH-05 test count is stale in README**: The breadcrumb says "94 tests total: Python (61), JS (33)" but the actual count is 121 Python + 11 JS + 26 frontend = 158. The breadcrumb should be updated or marked fully resolved. (`breadcrumbs/arch-05-no-test-suite.md`)
- **`runWithConcurrency` is not general-purpose safe**: If `fn` throws synchronously (not async), the promise rejection handling is fragile. This is fine for the current `runTask` (which is async and catches internally) but the helper would need `Promise.resolve()` wrapping to be reusable. (`calibration/run.mjs:271-282`)
