## On the project

The headline this session wasn't the work — it was discovering that the project's own disciplines had silently failed. Two prior sessions (Jul 10 evening, and early this morning) authored a complete v0.26 milestone — four excellent domain chapters, the authoring guide, the L4 reconciliation — and left no commit, no reflection, no memory, no work item. The only trace was file mtimes. The work was *good*, which made it invisible: nothing was broken, so nobody came looking. A project with 47 breadcrumbs and a reflection practice lost a milestone to the simplest failure mode there is. The disciplines here are genuinely strong — the review gate forced proper provenance on me when I resolved the WIs (reviewer ≠ accepter, lineage checks), the calibration README's failure taxonomy made the adversarial reviews sharp instead of vague — but they all share one assumption: that the session ends with a commit and a reflection. When that doesn't happen, everything downstream is blind. Worth saying plainly because the fix is cultural/hooks, not technical.

The authoring pipeline itself (chapter → authoring guide → pilot scenario → adversarial review → calibration) is the best-designed part of the project. The pre-kickoff note that pilots should precede full scenario sets is exactly right: the pilots surfaced rubric-pattern lessons (the level-inflation overshoot pattern) that will make the full sets cheaper.
